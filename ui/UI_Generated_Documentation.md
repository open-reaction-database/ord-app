# 📘 ORD Frontend Project Documentation

> The following documentation is generated by AI from transcription of architecture overview discussion

## 🧱 Project Overview

ORD (Open Reaction Database) is a web application built with a React frontend and a Python-based backend. It supports creating, editing, templating, and enumerating chemical reactions with group-based access control.

---

## 🛠 Technologies Used

### Frontend

- React
- Redux + Redux Thunk
- TypeScript
- Vite
- Mantine UI + Form libraries
- Ketcher + Indigo (for reaction previews)
- WebAssembly (via Indigo/Ketcher)

### Backend

- Python
- Protocol Buffers (Protobuf)
- Auth0

---

## 📁 Project Structure

- `ui/`: React frontend root
- `ui/src/`:
  - `store/`: Redux logic (actions, thunks, reducers)
  - `features/`: Core feature modules (e.g., reactions, datasets, templates)
  - `common/`: Shared resources (icons, constants, formats)
  - `pages/`: Route-level components
  - `routes/`: Application routing
  - `types/`: TypeScript types and interfaces
  - `workers/`: Web workers (e.g., for previews, enumeration)

---

## 🧭 Application Flow

1. **Startup**
   - Load Auth0, initialize store.
   - Fetch user metadata (create default group if needed).
   - Lazy-load features via React Suspense.

2. **Entities**
   - **User**: Has identity info, must belong to a group.
   - **Group**: Container for datasets and users with role-based permissions.
   - **Dataset**: Collection of reactions, editable by group members.
   - **Reaction**: Core structured entity, based on Protobuf, but represented as JSON in UI.

3. **State Management**
   - Normalized using Redux.
   - Entities inside reaction are identified by IDs (client-generated).
   - Redux DevTools recommended for debugging.

---

## 🔁 Reaction Handling

- **Internal Representation**: Plain JSON object.
- **Conversion Logic**: Protobuf ⇆ JSON via converters (`toORD`, `toProtobuf`)
- **Forms**: Dynamic rendering from JSON schema.
- **Previews**: SVG generation via Indigo in web worker.
- **Sidebar**: Path-based nested UI management.

---

## 🧪 Templates & Enumeration

### Templates

- Reaction "forms" are reused with disabled fields and variable labels.
- Shared as immutable data.
- Templates list supports client-side name search (debounced).
- Support CSV-based enumeration.

### Enumeration

- CSV template + mapping
- Batched via worker
- Generates and saves reactions

---

## 🚦 Validation

- **Backend**: Protobuf-based validation
- **Frontend**: Custom validation, especially for unique names
- Optional fields stripped before conversion to Protobuf

## 🔧 Running the App

### Requirements

- Node.js ≥ v20
- Docker

### Setup

```bash
# From root
cp .env.example .env
docker-compose up -d

# In ui/
npm ci
npm run dev
```
